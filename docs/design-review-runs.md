# 可恢复的分批设计评审

世界、力量、人物和故事四项仍独立评审，结论绑定完整设计与所选计划版本。评审不会批准计划、锁定设计、写正文或采纳事件。

计划范围分两层：`plan/overview.targetChapterCount`保留全书或本次里程碑规模，`detailedThroughChapter`表示从第1章开始连续具备细纲的终点，`outlinedChapterNumbers`列出所有已展开章号（包括连续范围以外的章纲）。例如目标100章、目前细纲1–50章时，前50章须核对场景可执行性，后半本检查宏观因果、成长前置、选择代价和收束。不能仅因后半本尚未写逐场招式或逐日训练就要求一次性展开；也不能用分阶段规划掩盖已经存在的矛盾。新增细纲会改变评审指纹，必须重评，旧通过不能覆盖新范围。

## 原文与结论

- 原材料序列化后不超过 240,000 字符：一次原文评审，保留原来源 ID。
- 超过容量：按最多 10,000 个 UTF-16 字符切片（不切开代理对），保留来源 ID 和起止范围；每批普通原文序列化后不超过 100,000 字符，另可携带以下公共原文。
- 新调度（`scheduleVersion: 2`）为每个原文批次和跨批检查重复携带最多40,000字符的公共原文。力量优先带全书范围、公理、境界、品阶、功法和法宝；人物优先带范围、角色起点和世界规则；世界与故事优先带范围、规则和地点。每个公共来源完整选取，超过公共容量的条目仍完整进入普通批次，不截断或总结。单次最多是两批各100,000字符加一份公共原文，公共来源在同次请求内去重。
- 每个原文批次独立评审，再对每一对批次共同读取原文，检查跨批矛盾。最后用二叉树综合全部原文和跨批报告。单次来源仍受 240,000 字符上限约束，不截断原文或模型结论。
- 原文批次数为 n 时，原文与跨批评审共 n(n+1)/2 次，加上综合共 n(n+1)−1 步。最多 64 个原文批次；这是上限而非建议规模，较大材料的调用量和费用会显著增加。
- 每个结果最多 40,000 字符，证据必须精确匹配本次输入。综合引用的是前置报告，不冒充直接引用原文；前置报告及原始证据始终保存在批次记录中。
- 最终提交重新核验切片范围、完整调度、所有阶段的证据，并保留每项标准最严重的判定。多个问题的完整解释保留在各批记录中，综合模型不能把先前的返修或材料不足改成通过。

覆盖校验只能证明材料确实被安排送审，不保证模型理解无误。局部通过、全量步骤完成、设计通过、批准计划与正文验收是不同状态。模型意见需要结合原文核对；仍需人工修订和重新评审。

## 执行与恢复

`POST /works/:workId/design/review-runs` 创建或恢复同版本同领域的未完成任务；请求体为 `{area, planId?}`。不调用模型。

`POST /works/:workId/design/review-runs/:runId/step` 只执行一个步骤。每步保存结果、尝试次数、失败历史和模型原答。前端循环推进，可选择“本批后停止”；刷新或服务重启后“继续本项”从未完成处恢复。已有步骤不重复调用。

`GET /works/:workId/design/content-reviews` 返回版本、结论和进度摘要。`GET /works/:workId/design/review-runs/:runId/stages/:stageId` 查看该批输入和记录；综合阶段需前置批次完成才能构造输入。

模型请求在数据库事务外执行，以带心跳的租约和令牌防止并发覆盖。失联进程租约到期后可以重试；旧进程无法覆盖新结果。设计改动后旧任务不能继续，必须重新开始。新一轮未完成评审会挡住旧的通过结论。旧同步评审接口兼容保留，但浏览器采用逐步接口。

没有`scheduleVersion`字段的旧任务仍按原调度恢复、校验和结束，不重排已经评过的材料。公共原文只影响新建任务；继续旧任务不会补加上下文，也不能把其“本批缺材料”结论自动改为通过。新调度减少章纲与基础规则被拆开的误判，但40,000字符不能覆盖所有依赖，仍须核对模型是否误把局部未见当成全书缺失。

## SQLite 升级

停止 API 后，在仓库根目录执行：

```sh
python3 scripts/migrate-design-review-runs.py data/novel-studio.db
npm run generate -w novel-studio-persistence
npm run dev:api
```

迁移使用 SQLite backup API 在同目录的 `audit-backups` 保存备份，再向 Project 新增 `designReviewRuns TEXT NOT NULL DEFAULT '[]'`。重复执行不修改已有字段；不重置数据库或改写计划、正文、事件。原有 JSON 仓库缺少此字段时按空数组加载。

PostgreSQL 部署需在自己的迁移流程中添加 `"designReviewRuns" JSONB NOT NULL DEFAULT '[]'::jsonb`，再按 PostgreSQL schema 生成客户端；本次恢复验证覆盖 JSON 与 SQLite，未在 PostgreSQL 实例上实测。

评审指纹版本已升级，旧报告仍保留，但须用新流程重评后才能再次作为当前设计的放行证据。
