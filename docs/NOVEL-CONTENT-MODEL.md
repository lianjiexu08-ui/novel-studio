# 百万字玄幻小说内容模型

版本：v1.0  
日期：2026-10-10（Asia/Shanghai）  
状态：百万字长篇创作的领域设计基线

## 1. 目标

一本数百万字的玄幻小说不能只按“生成下一章”运行。系统需要同时维护：

- 作者确认的世界真相；
- 世界在故事时间中的变化；
- 每个人物在不同阶段的目标、关系、能力、知识和选择；
- 力量体系、功法、资源、法宝和代价；
- 地理、势力、制度、历史、文化与超自然公理；
- 全书、分卷、主线、支线、场景、伏笔和承诺；
- 正文事实、角色认知、未来计划和模型推断之间的边界。

系统的权威来源是版本化正文、作者锁定设定和带证据的故事事件。摘要、检索索引、人物卡投影和图谱都是可以重建的派生数据。

## 2. 作品层级

创作结构固定为：

`Series（系列） → Work（一本书） → Volume（卷） → Arc/Subplot（主线或支线弧） → Chapter（章） → Scene（场景） → Beat（节拍）`

不要求一次性细化数百万字。全书确定终局方向和主要弧线，当前卷细化到场景，接下来 5—10 章进入可执行计划。卷末根据已采用正文重新规划下一卷，但不能悄悄改变作者锁定的核心承诺。

每个 Volume 至少记录：目标、冲突、起始状态、结束状态、高潮、参与人物、势力变化、力量阶段、必须回收的开放线、预计章节和收束条件。

## 3. 内容真相的分层

所有重要内容必须标明所属层：

1. `AuthorCanon`：作者确认或锁定的世界设定。
2. `Planned`：未来计划、人物弧光、伏笔安排和候选方向。
3. `ObservedStoryFact`：已经采用正文中有证据的事实。
4. `CharacterBelief`：人物相信、误解、传闻或公开说法。
5. `ReaderDisclosure`：读者已知但角色未必知道的信息。
6. `DerivedProjection`：从事件重建的当前状态、摘要和索引。

计划不能直接成为事实，读者真相不能自动进入人物上下文，角色的谎话和误认不能覆盖世界真相。

每条动态记录至少带：实体 ID、操作、前后值、故事时间区间、正文版本、证据段、来源类型、置信度、有效性和失效原因。

## 4. 世界圣经

`WorldRule(category, title, content)` 只能作为说明文字，不能承担百万字世界模型。世界圣经拆成以下对象：

### 4.1 宇宙与自然法则

- `WorldLayer`：世界、界域、位面、秘境、内天地和附属空间；
- `SupernaturalAxiom`：灵魂、复活、转世、预言、时间、因果、传送、记忆和身份规则；
- `Calendar/Era`：纪元、历法、时区、年龄和寿命规则；
- `RuleScope`：全局、界域、地区、势力、人物或功法例外。

规则冲突必须显式记录优先级、适用范围、例外、代价、反制和证据，不能由模型临场补设定。

### 4.2 空间与地理

- `Location`：大陆、国家、区域、城市、宗门、秘境、遗迹、房间；
- `WorldEdge`：相邻、包含、控制、通往、敌对、贸易和依附；
- `Route`：起点、终点、距离、交通方式、耗时、门槛、费用和风险；
- `TeleportRule`：传送点、冷却、消耗、限制和失败后果。

角色移动必须能从地点、路线或明确的传送规则重建。不能因为地点名称同时出现在上下文，就认为移动合法。

### 4.3 历史、势力与文化

- `HistoricalEvent/Era`：时代、参与者、原因、后果、客观事实与不同叙述；
- `Faction/Institution`：目标、意识形态、层级、辖区、资源、职位、法律和权限；
- `Membership/Office/Jurisdiction`：成员、职位、管辖范围和有效时间；
- `Species/Culture/Religion/Language`：寿命、礼制、禁忌、称谓、风俗和技术基线；
- `Economy/ResourceMarket`：货币、资源产出、稀缺程度、贸易和制度限制。

势力关系、职位和辖区都有开始与结束时间。历史真相、官方叙述、民间传说和人物误信分开保存。

## 5. 玄幻力量账本

力量体系是独立领域，不能放在一个 `power` 类世界规则中。

### 5.1 体系与境界

`PowerSystem` 记录力量来源、转换方式、计量单位、全局上限、修炼路线和规则优先级。

`RealmTier` 记录顺序、能力范围、突破前置、资源、仪式、时间、失败后果、寿命代价、相克关系和跨体系可比性。

### 5.2 功法、能力、血脉与法宝

- `Technique/Ability`：使用者条件、效果、目标、范围、持续时间、消耗、冷却、反制和禁用条件；
- `Lineage/Physique`：来源、遗传、觉醒条件、代价和限制；
- `ItemDefinition/ItemInstance`：法宝、丹药、材料、唯一性、耐久、充能、绑定和损毁；
- `ResourceDefinition/ResourceLedger`：来源、数量、单位、品质、转移、消耗、恢复和稀缺性；
- `PowerState`：人物在某个故事时间的境界、熟练度、伤势、封印、欠债和副作用。

突破、能力使用、物品转移和资源消耗都必须成为带正文证据的事件。未满足前置条件时采用阻断；越级、复活、时间回溯和因果改写必须引用已定义的显式例外。

## 6. 人物与关系账本

### 6.1 人物

静态身份和动态状态分离：

- `CharacterProfile`：稳定 ID、姓名、别名、称号、真实身份、出生、寿命、声音、价值观和作者锁定项；
- `CharacterStateFact`：地点、年龄、身体、伤势、境界、功法、能力、物品、势力职位、目标和当前处境；
- `KnowledgeBelief`：人物知道什么、相信什么、误信什么、从哪一事件获知、可信度和有效时间；
- `Secret/Revelation`：秘密所有者、读者知情、角色知情、揭示条件和实际揭示事件；
- `ArcPlan/ArcBeat`：初始信念、触发、理解、关键选择、代价、后果和目标状态；
- `CastRole`：人物在某卷的目标、利益、拒绝条件、独立决定、引发变化和承担后果。

人物可以成长、退步、停滞或维持稳定。系统检查的是选择和后果是否有依据，不是强迫所有人物正向成长。

### 6.2 关系

关系按维度拆开，允许同时成立：

- 客观血缘与身份；
- 师徒、隶属、婚姻和社会职务；
- 方向性的信任、情绪和利益；
- 公开立场与私下意图；
- 人物对彼此关系的认知或误信；
- 势力、职位和权限关系。

每条关系带方向、有效起止时间、来源事件、证据、可见范围、强度、锁定级别和当前版本。兄弟可以互为仇敌，信任不要求对称。死亡、夺舍、分身和转生需要新的身份连续性记录，不能复用同一个人物 ID 消除历史。

## 7. 剧情、开放线与收束

剧情对象至少包括：

- `BookGoal`：核心承诺、终局方向和不可悄悄改变的读者期待；
- `VolumeArc`：卷目标、升级、高潮、代价和结束状态；
- `Subplot`：服务对象、推进节点、主题作用、依赖和收束条件；
- `Foreshadow/Revelation`：埋设、允许提示、揭示窗口、兑现证据；
- `Obligation`：誓约、承诺、交易、期限、触发条件、后果和履行证据；
- `OpenLoop`：已经向读者或角色提出、必须回收或明确放弃的悬念。

状态统一使用 `planned → setup → active → partial → paid_off / abandoned / diverged`，每次状态变化关联采用章节和证据。

一本书的完稿条件必须检查所有 `must_close` 的开放线、主线节点、核心人物弧光、义务和结局要求。

## 8. 时间、空间与事实重建

故事时间不能只用一个可选整数。事件应支持明确日期、区间、相对顺序、持续时间、因果前置和叙述顺序。系统需要提供：

- `stateAt(chapterVersion)`：某章之后的客观状态；
- `knowledgeAt(character, chapterVersion)`：人物当时可用的知识；
- `worldAt(location, storyTime)`：某时空规则、势力和历史截面；
- `powerAt(character, storyTime)`：境界、能力、资源、伤势和代价；
- `openLoopsAt(chapterVersion)`：当时未回收的伏笔、承诺和悬念。

源事件追加保存，当前状态只是投影。每 10—20 章和卷末保存 `StorySnapshot`，从最近快照加事件增量重建，不能每次加载数百万字全文。

## 9. 百万字上下文策略

每章上下文按优先级分层：

1. 作者硬约束和本章必需规则；
2. 当前场景人物、关系、位置、力量和资源状态；
3. 本卷摘要、当前主线、支线、开放线和前置条件；
4. 最近章节正文；
5. 按实体、事件和依赖召回的远期证据；
6. 文风参考和可选历史材料。

`ContextManifest` 必须记录纳入项、来源版本、证据、召回原因、省略原因、token 估算、容量状态、canon hash 和 state hash。必需资料不足时返回 `needs_split` 或 `blocked`，不能始终标记为 complete。

## 10. 卷末与全书质量门

质量分三层：

- 章节：时间、地理、人物知识、关系、力量、资源和正文证据；
- 分卷：主线推进、人物弧、群像 agency、势力变化、节奏、伏笔和义务；
- 全书：核心承诺、结局、开放线回收、跨卷一致性、文风统一和最终稿完整性。

作品区分：

1. `story_complete`：故事内容已收束；
2. `manuscript_complete`：全书修订、校对和快照已固定；
3. `publication_complete`：投稿、连载或导出交付完成。

## 11. 实施优先级

### P0：长篇创作基础

- 统一 SQLite 与 PostgreSQL 的领域契约；
- 增加 Volume/Arc/Scene、写作游标和持久化 Run/Checkpoint；
- 将 CharacterState、Knowledge、RelationshipTimeline、PowerState、WorldEntity 事件化；
- 增加 `constraintRevision`，设定修改必须使旧候选失效；
- 修复新运行从第 1 章重跑的问题；
- 实现分层 ContextManifest 和按章节的状态查询。

### P1：玄幻内容校验

- 地点、路线、势力、历史和时间线；
- PowerSystem、Realm、Technique、Item、Resource；
- 人物弧、群像职责、伏笔、开放线和 Obligation；
- 时间、移动、力量、资源、知识和关系确定性检查；
- 卷末 StorySnapshot 和复盘报告。

### P2：完稿与交付

- 分支与合并；
- ManuscriptRevision/BookSnapshot；
- 全书质量门和三种完成状态；
- 最终导出、投稿快照和发布归档。

百万字的核心不是把更长的正文塞进提示词，而是把世界、人物、力量和剧情都变成带时间、版本、证据和影响关系的账本。
