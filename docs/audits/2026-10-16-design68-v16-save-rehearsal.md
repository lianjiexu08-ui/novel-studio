# Design68 合并草案v16的隔离保存演练

本次演练成功，生产作品未改。通过SQLite只读连接及backup API建立一致副本，在副本中调用冻结版本的真实 `saveDesignCandidate`，断开后另建仓库连接重新读取。

保存结果仅在隔离副本中形成世界v35、圣经v66、计划v69，批准计划仍为v10。除服务器版本和绑定字段外，完整内容与v16候选精确一致；50条详细章纲、100章宏观目标、40条执行要求和41条未解决阻塞全部保留。

以下原记录逐项哈希匹配，数量没有减少：68份计划、99份设计快照、101个章节版本、383条事件、1份书稿、116个候选、67份评审任务及72份报告。副本仅增加两份设计快照和一份提案计划。包括正在评审的原任务在内，旧记录没有被重写。

重新读取的副本生成了四领域的实际评审输入。这次使用真实保存后的输入绑定，区别于此前只替换五份来源的合成容量探测；这些新ID和哈希只属于副本，不能用于生产评审。每份来源的分片覆盖连续完整，实际请求文本与对应原文切片相等；66个初始请求全部满足材料与元数据限制，最大材料为219,579字符。

候选仍是暂定v16。正式四领域评审尚未全部结束，后续发现可能要求继续修改；本演练不代表内容通过，不验证动态补读，不批准计划，不生成正文。生产中的世界v34、圣经v65、计划v68评审继续运行。

对应 `.mjs` 为执行脚本，`.json` 保留副本路径、候选哈希、输入哈希、逐请求容量与历史数量。副本由只读源连接创建，路径和设备/inode隔离均有断言；脚本只向该副本保存设计。重跑需要另建副本并保留原始演练记录。
