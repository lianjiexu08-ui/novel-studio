# 分批章纲生成期间的版本检查

发现全书规划和局部章纲生成只在保存时校验最新计划 ID。若模型等待期间修改世界规则、故事圣经、创作约定，或采纳新正文，最新计划 ID 可能不变；旧输入生成的结果会被新建修订自动绑定到变化后的世界与圣经。内存仓库还会将同一可变设定对象交给多个批次，造成一次生成混用前后输入。

先增加真实异步等待的回归场景：全书规划与局部章纲各覆盖上述四种变化。旧实现八项均以 `Missing expected rejection (PlanConflictError)` 失败。修复后，生成开始时复制规划输入与原批准计划，捕获故事状态修订、约束修订、批准计划 ID 及最新提案 ID；每个章纲批次开始前、返回后，以及最终保存事务内再次核对。任一基线变化即以现有 `PLAN_CONFLICT` 错误拒绝保存，已有计划与正文保持原样，并停止后续模型批次。

局部重生成若一开始就选了旧提案，现在在调用模型前拒绝。沿用现有保守版本语义：约束修订推进也会使本次规划失效，需要刷新重试；不自动合并不同输入生成的章节。此改动没有新增分批草稿持久化，失败生成的未提交输出不会伪装成有效新计划。

验证包括八个等待中变更场景、两条事务排队期间变更的路径，以及生成骨架期间批准另一份计划的场景。事务测试让作者修改占有队列，模型和只读检查先结束，随后才提交作者修改，确认最后一道事务内检查仍会拒绝旧结果。原有正常分组生成、局部替换与历史不变测试继续通过。

隔离副本全量 **293 项测试通过**，前端类型检查与构建通过。日志：`/tmp/novel-planning-baseline-before.log`、`/tmp/novel-planning-baseline-target-v2.log`、`/tmp/novel-planning-baseline-all-tests.log`、`/tmp/novel-planning-baseline-build.log`。

所有复现使用本地测试提供者，未额外调用真实模型、修改正式设计、批准计划或生成正文。正式 59 的冻结复评继续运行；此补丁待写入者退出后统一部署。
