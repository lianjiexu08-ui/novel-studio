# 设计 62 续跑的并发读取故障修复

续跑第一次尝试在调用模型之前失败：两名 worker 同时读取作品，Prisma `project.findUnique` 返回 `Failed to convert rust String into napi string`。该次模型调用为 0、派发步骤为 0，四个评审任务仍与原始终止检查点完全相同，全部 69 个完成步骤保留。原失败文件留在 `resume-1-result.json`，没有覆盖或删除。

对生产库只读复现：同一仓储的两个并发 get 均报上述错误，连续三次串行 get 均成功。此作品保留的评审报告和任务字段合计约 248 MB，另有设计历史。这里证明的是并发读取触发故障；未将其宣称为数据库损坏，也未清理历史来规避问题。

恢复入口改为单 worker，逐步读取和派发；冻结评审代码、模型、提示、原文覆盖范围和预算均不变。新增 `--attempt=N` 只允许跨过“零派发、零模型调用、持久化任务与原始断点完全相同”的失败尝试，记录各失败文件哈希，分别写入新输出文件。任何已有模型消耗或新步骤状态都必须重新绑定恢复入口，不能凭这个参数重复执行。

验证包括：生产只读预检通过；独立 SQLite 备份中的模拟失败只将 `synthesis-15` 的尝试次数从 1 增至 2，旧失败仍在，所有 69 个成功步骤及受保护设计、计划、正文和历史保持不变，模型与网络调用均为 0；分别注入模型消耗、步骤派发和持久化进度差异，重试守卫均拒绝。

正式第二次尝试使用当前配置连接，从原任务续跑，输出另存 `resume-2-result.json`。该启动本身不证明额度恢复或质量通过；后续以模型返回和持久化报告为准。本修复不批准设计，也不生成正文。
