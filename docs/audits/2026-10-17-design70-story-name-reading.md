# 提案 70：综合把“林远在”误读为人名笔误

`synthesis-12/timeline` 返回 `pass`，但称前置报告中“林远在赤霄”与所引里程碑的“林辰”不一致，“应视为报告笔误”。这个笔误判断没有上下文支持，不是已发现的人物设定错误。

原 `followup-cross-1-2/timeline` 同一段先写“苏凌霜返宗侧回顾与林辰赤霄线，而非要求林辰同时在两地”，随后写“后者明确林远在赤霄且至第41章才获知返宗消息”，再继续用“林、贺青梧”。这里是简称“林”加方位叙述“远在赤霄”，没有声明名为“林远”的另一人。

所引 `ms_bridge_return` 原文也正是“林远在赤霄，第41章收到苏226日寄出的信后才知道他们已安全返宗”；并非报告擅自把来源中的另一个姓名抄错。人物档案 `char_01` 的规范名仍为林辰。实际综合输入中能找到这段前置解释和相同的里程碑引文，本次并非材料缺失。

同名 JSON 保存原解释、规范人物身份及来源指纹、完整里程碑、综合检查、实际输入文字位置、原请求及不可覆盖检查点指纹。冻结运行时离线重放了该综合的一条实际响应，结果一致。本次未调用模型、修改报告或设计；不得据这条没有依据的笔误判断改人物名、地点或时间线。后续须观察它是否继续传播这个判断，但不把原文正确的简称当作新的设计返修项。

完成后的追踪：综合 19 重复了“报告中‘林远在赤霄’与原名不符属笔误”，但仍沿用林辰的正确路线。综合 22、24及最终综合25的摘要和解释均未再重复这个笔误判断，也未显式撤回它。两次错误判断继续保留在[故事完成核验](2026-10-17-design70-story-complete.md)绑定的完整检查点中；后来的省略不能冒充对历史措辞的显式裁定。
