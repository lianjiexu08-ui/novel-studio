# 补读复核记录可直接追溯原问题与解决依据

最终报告此前仅把补读关系显示为 `checkId → resolvedByStageId` 文本。面对数十个批次，作者需要手动寻找原问题与后续证据。现在每条复核记录提供“查看原补读问题”和“查看解决依据”入口，定位报告所属的原运行，不转向当前设计或新任务。含斜杠的嵌套补读步骤按完整保存编号匹配；旧报告没有可定位的批次时保留编号并明确详情不可用。

批次详情同时增加立即可见的加载状态、失败提示及重试。请求序号在打开新批次、关闭详情及切换作品时更新，迟到响应不能覆盖后选批次或重新打开已关闭详情。

隔离工作区完成前端 TypeScript 检查和 Vite 构建；浏览器在5181的合成样例中验证了原问题、嵌套补读编号、解决依据、慢请求、503重试以及关闭后迟到响应。样例明确标注不属于正式小说评审，所有请求由隔离页面返回，无生产写入或模型调用。截图与构建日志路径见同名 JSON。此次仅修改显示和导航，未修改后端判定，也未增添镜像实现的单元测试。

正式API8787、冻结UI5180和design63运行版本未部署本改动；130个冻结后端源文件哈希仍一致。41条阻塞、历史正文和评审记录均未调整。该界面验证不证明正式设计通过。
