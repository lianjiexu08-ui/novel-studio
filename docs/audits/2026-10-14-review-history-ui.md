# 旧版评审批次在界面中保留入口

原界面只展示当前设计的最新任务，以及已经形成的最终报告。设计版本变化或同一设计再次评审后，较早任务的批次入口会消失；未形成总报告的失败任务尤其无法在页面上查阅。

新增“历史评审任务与批次”，保留旧版本及同一设计较早任务的全部批次入口。每项显示绑定的世界、人物圣经和计划版本、创建时间、已完成步数及材料数量。失败批次仍可打开原文、模型回答和失败原因；曾执行但尚无结果的批次也有详情入口。历史区域不提供启动旧任务的按钮，当前继续评审仍使用原入口。

批次详情标题包含计划版本；与当前所选设计指纹不同时提示仅供历史核查。失败批次没有结果卡时也显示完整版本信息，避免误把旧评审当作当前结论。前端详情类型补齐服务端原已返回的`inputHash`，没有修改API或评审逻辑。

验证在`127.0.0.1:5180`使用真实作品进行，只查看记录。页面列出33个历史任务；展开计划45的世界评审（0/1步、没有最终报告），成功打开批次1，显示世界20、圣经45、计划45、222项原始材料入口及“证据片段不属于本次材料”的既有失败原因。弹窗正确显示历史版本提示。截图保存在忽略目录`data/audit-backups/2026-10-14-review-history-ui.png`。

最终Web类型检查及生产构建通过（`npm run build -w novel-studio-web`），仍有既有的大包警告；`git diff --check`通过。此次仅调整展示，没有重启API、启动新模型评审、保存设计、批准计划或生成正文。正式57世界/力量评审和候选专项队列继续按原顺序运行。
