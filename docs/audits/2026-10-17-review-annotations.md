## 核对记录的读取频率

核对记录列表接口目前仍通过 `repository.get` 读取作品聚合。若沿用父组件的 `refreshedAt`，每次评审进度轮询成功，所有已经挂载的报告/批次核对列表都会再次读取历史数据，即使评审进度没有变化。历史评审原文较大时，这会额外放大读取开销。

现改为进入报告或批次时加载，并提供单独的“刷新核对记录”按钮、加载状态、最近成功读取时间和空列表提示。记录读取失败仍显示错误并支持重试；切换任务时清除旧记录并忽略过期响应。评审进度继续自动刷新。通过 API 在别处新追加的说明需要点击刷新才能出现在已经打开的列表中，界面明确提示这一行为。

本次仅减少重复触发，没有声称解决单次聚合读取开销，也没有修改后端引文验证。隔离源码副本的前端类型检查与构建通过（日志 `/tmp/novel-review-notes-refresh-build.log`，仍有既有大包提示），`git diff --check` 通过。本次刷新交互未额外进行浏览器验证，生产网页和评审进程未重启。
