# 汇总重验复用只读计算

在上轮将完整重验移出数据库事务后，使用设计 58 世界评审保存的 53 步数据进行 CPU 采样。约 25 秒耗于反复扫描相同功法、法宝、资源与人物/章纲的提及关系；补读来源集合与递归报告也反复重建。

本次增加单次同步只读校验内部的缓存，复用提及索引、完整补读来源集合和渲染后的前置报告。缓存不写进任务、不跨调用保存、不在接受新步骤后继续使用；重建可变的预期调度时，每次接收结果仍独立重验。最终综合仍遍历并验证每个步骤，检查完整覆盖、引用、补读解除条件及全部未解决的负面判断。

## 真实数据比较

固定同一份失败任务及已保存的最终答复，分别用优化前后的代码执行，不调用模型、不写数据库。去掉 CPU 采样后的复测结果：

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 接受最后一步 | 6,085 毫秒 | 449 毫秒 |
| 完整汇总重验 | 32,141 毫秒 | 625 毫秒 |

全部 485 项来源与最终结果合计 1,969,651 字符，完整序列化对象 SHA-256 均为 `d316378a65de067cb4e69236d89d125b526534a91aac2388f02d80d0905c51e2`。首次采样、未采样基线及两次优化后输出一致。地理仍需返修，历史与百章容量通过；没有把执行成功当成内容验收。

这是单份真实数据的回放结果，不是对所有长篇规模的耗时保证，也不包括数据库加载与写入。原始采样和回放脚本已保存在忽略的审计备份；简明结果见同目录 `2026-10-14-review-read-cache-benchmark.json`。

## 验证与运行边界

47 项针对性测试通过，新增用例验证原文被就地修改后会重新定位、调用方修改返回索引不会污染后续读取、完整评审通过后再篡改引用仍会拒绝完成。隔离全量 272 项测试、前端 TypeScript 与构建通过，保留原有大包体积提示。

调度版本不变，原文、来源顺序、报告文本、容量限制与历史解除规则不变。正式恢复进程继续使用其冻结代码，未在运行中替换模块。原库、当前保存的设计和已采纳正文均未改变；候选 59 仍待正式验收。
