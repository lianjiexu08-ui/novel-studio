# 可恢复的设计文本修订界面

世界构建页新增「修订设定与全书计划」。作者可以搜索世界、功法、人物关系、认知阶段、分卷和章节等已有条目，修改文本及文本列表，再查看每项改前/改后，通过整套原子接口另存待评审提案。该入口处理已有文本修订；新增实体、改变章节区间和引用结构不在此编辑器范围内。

草稿连同原编辑基线保存在当前浏览器的IndexedDB，刷新或重新打开会恢复。存储写入串行，界面明确显示保存中、已保存或失败，成功提交后再清理旧草稿。并发修改造成旧基线冲突时保留草稿和差异，拒绝覆盖；作者可核对后主动放弃草稿并重新载入。列表中每条文字独立编辑，多行内容不会按换行重拆成多个条目。引用、身份标识、日期区间、锁定和问题处理状态均不在文本编辑字段内。

整体草稿导出现在会把设定集的版本绑定对齐当前世界：单独更新世界后仍能修复整套设计。乐观校验哈希继续依据原始存储内容；导出操作不改变旧设定集或历史。界面仅在API声明支持整体保存时显示新入口，避免新界面向冻结旧服务调用不存在的接口。

## 验证结果

- 隔离工作区执行 `node scripts/test-all.mjs`：372项测试通过，包含严格core类型检查、新增文本编辑/差异测试及既有原子保存、回滚和并发测试。
- `npm run build --workspace apps/web` 通过TypeScript检查和构建；Vite仍提示已有大块体积，未影响构建。
- 在8791内存API与5182测试界面，通过真实浏览器操作验证：修改世界摘要；刷新后恢复草稿；搜索功法条目；多行限制编辑；改前改后预览；模拟另一编辑者更新世界后保存被拒；冲突后改稿可读；主动重载；再次编辑并保存为计划v2待评审提案；关闭重开后旧草稿已清理。
- API读取验证：当前批准版仍为v1，最新v2为proposed，另一编辑者已保存的世界摘要未覆盖，功法仍为原来的两条限制且第一条完整保留新增换行，设定集绑定与世界版本一致。
- 验收中的长对比内容使用滚动区域，底部保存按钮保持可见；成功后的刷新不会让模态框丢失保存结果。截图保存在忽略目录 `data/audit-ui/design-revision/`。

全部浏览器写入仅针对临时内存作品，未写生产数据库、未调用模型、未生成正文。测试页面及8791/5182进程已关闭，5173未使用。冻结61评审服务仍保持原运行版本；正式设计修复须等故事线最终意见归并，不能由界面验收代替内容验收。
