# 模型空闲超时与网络层等待上限

正式 59 的世界项 `followup-batch-2/history` 和力量项 `cross-3-4` 均在等待模型响应头时收到 `UND_ERR_HEADERS_TIMEOUT`。保存连接的 `timeoutMs` 为 600,000 毫秒，但 Node 原生 fetch 的下层默认响应头限制可在约 300,000 毫秒提前结束请求。世界已完成 16 步、力量 12 步及原失败记录均保留，失败步骤没有可复用的完整模型答复。

模型适配器现在仅对原生 fetch 的模型请求附加 dispatcher，显式取消底层响应头和响应体的独立超时，继续使用原有 AbortController 的配置空闲期限：长时间没有输出仍会中止，连续收到数据会重置空闲计时。dispatcher 委托当前全局 dispatcher，保留原网络连接配置；不替换全局设置，自定义注入 fetch 不改写，也不增加重试或回退模型。

引入锁定解析为 7.30.0 的 `undici`。工作区只写依赖清单／锁文件，并补入这一个依赖目录；没有运行安装生命周期或生成 Prisma 客户端。隔离目录安装依赖后发现旧 `.bin` 目录仍是工作区的共享链接，初次前端构建因此解析到缺少可选本机包的工作区 Rollup。已仅移除隔离目录的链接、重建本地可执行链接后重新构建通过；原链接指向的工作区目录未删除。此前安装过程可能重写该共享目录内的可执行链接，不能声称安装完全未触及任何工作区依赖路径；正式 API 和冻结运行器未重启。

验证使用本地 HTTP 服务，不调用外部模型：

- 旧实现的原生请求没有显式超时覆盖，断言失败；新实现通过诊断通道确认实际请求的 headersTimeout／bodyTimeout 均为 0，避免只检查构造参数却被 fetch 覆盖。
- 模型空闲期限仍中止不返回响应头的服务，且请求只有一次。
- 持续传送的流式回答可超过总的空闲期限并完整结束。
- 隔离全量 276 项测试通过，前端类型检查和修正环境后的构建通过；工作区额外运行 3 项真实网络测试通过。
