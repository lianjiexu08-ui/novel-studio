# 关系快照来源修复

## 问题与改动

章节关系重建在没有已采用事件时会回退到故事圣经中的关系阶段。原界面把回退值与正文事实同列为关系快照，没有区分来源，容易把“计划结盟”理解成已发生。

本次保留原来的回退和生效范围规则，为结果增加三种来源：`author_setting`（作者设定）、`story_plan`（创作计划）、`adopted_event`（正文事件）。正文事件返回引文、事件 ID、章节版本和发生章；计划返回故事圣经版本、阶段范围、触发原因及代价。失效事件不能继续标为正文事实。其他作品的事件不参与重建。接口过滤不存在的关系，前端兼容旧接口的空项和无来源记录，后者显示“来源待核对”。

质量页逐行显示来源，展开后可查看依据。设定锁定与正文事实分别展示，避免将锁定误当作落实证据。

## 验证

- 新增接口回归测试：作者设定、计划生效范围、阶段原因和代价、实际分歧覆盖计划、实际变化在计划结束后保留、事件失效后的计划回退、只读重建及 DTO 校验。修复前测试失败，修复后通过。
- 隔离副本完整测试：315 项通过，0 失败；构建通过，仅有既存前端产物体积提醒。
- 隔离浏览器验证：内存仓库临时 API `52801`，临时前端 `5181`。确认“作者设定 / 创作计划 / 正文事件”三种标签及展开内容；计划结盟与实际决裂并列时来源清楚，正文引文和版本可见。截图：`/tmp/novel-relationship-provenance-ui.png`。
- 验证结束关闭临时页面和两个临时服务。未操作 `5173`，未重启生产 API，未迁移数据库，未改写作品设计、已采用正文或历史评审。

## 限制

这是来源可见性和重建接口修复，不是故事圣经或正文的质量验收。生产仍运行评审恢复开始前的部署；待正在执行的评审结束后再安排更新。四项评审与现存阻塞仍需逐项核对，不能以本次测试通过替代设计验收。
