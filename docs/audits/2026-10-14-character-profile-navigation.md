# 人物前史进入力量评审导航

## 已确认的问题

设计 58 力量正式评审 `cross-2-3/tiers` 曾要求补齐顾峤的真光训练。完整人物档案 `story/characters/char_10` 已有开篇前纯阳供能、凝印、收势、受控实测与经脉复诊，但该批实际提供人物档案 0 字；此前功法提及索引只检索章纲和里程碑，不能指向这份前史。完整目录有材料不等于模型已经读过，旧返修也不能据此自动改为通过。

## 修复

新建任务使用调度版本 19。功法、法宝和资源的原名或完整 ID 提及索引增加 `story/characters/`、`settings/characters/`。否定句同样只是定位线索，不能证明掌握；没有命中不能证明不存在训练。

补读功法规则时，相关人物前史可作为完整原文随章纲一起补充，仍受原有容量限制。放不下的可选来源整体省略并标明，不能截断档案、挤掉必要证据或消除原问题。提示词明确区分开篇前训练与本场伤情、余额、冷却，不从身份推断技能。

版本 1—18 保持原索引与分块协议。正在运行的版本 15 正式评审使用冻结运行目录，本次不改变其运行协议，不重启服务、不迁移数据库、不保存新设计。

## 验证与限制

- 69 项针对性测试通过，隔离环境全量 268 项测试通过，前端 TypeScript 和构建通过（保留已有的大包体积提示）。覆盖肯定/否定前史、完整 ID 与相近 ID、旧版本兼容、补读完整档案及容量不足时不裁切/不挤掉必要原文。
- 原失败批次离线回放：版本 18/19 的 191 项原文完全相同，共 216,775 字符。957 字的顾峤档案存在于完整目录但未实际提供；新索引能准确指向该档案。此项仅验证材料定位。
- 相同原文的真实模型回放使用保存的 `gpt-5.6-luna`，无回退，一次调用，输入 160,184 / 输出 3,821 tokens。三个标准均为等待补读的不足，未明确索要顾峤档案，且漏报原稿第 25 章血爪时序矛盾。因此不能声称新索引已经让大批次评审稳定识别问题，也不能凭此次答复撤销旧返修。
- 全量请求及回答保存于忽略的审计备份；跟踪的摘要保留上述漏检。复查确认保存的设计、正文、采纳历史与旧报告均未改变。

补充小范围诊断使用原设计 58 的 31 项完整来源（36,599 字符），仍使用同一模型且无回退。人物资格通过，证实其既有训练原文足以核验；战斗也被判通过，模型把“末次扑抢”解释为真光前的两息出爪，与原正式负面报告不同。这说明局部模型结论仍不稳定，不能按新通过覆盖旧返修，更不能认为它验证了候选设计 59。两份诊断全部留档，不反复重试直至得到期待结论。

离线候选稿已把起印、两息出爪、付款与停术明确绑定到同一时间线，消除这种靠解释补齐的空间；候选尚未保存或验收。正式质量门禁继续阻止批准计划与续写。
