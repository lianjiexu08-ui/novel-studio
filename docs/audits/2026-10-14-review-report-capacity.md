# 原文引文展开后的报告容量检查

## 实际失败

设计 58 的故事正式复评在 `synthesis-16` 失败，已完成 34/37 步。该步骤只综合部分报告，不是最终验收。回放保存的真实模型原答并重新解析同一请求、同一片段编号，得到完全一致的引文与判断：

- 模型原答只有 3,200 字符。
- 76 条引文展开并加上来源位置、独立摘录标记及 JSON 转义后，报告包为 **105,497 字符**，超过 **90,000** 上限。
- 原输入为 138,119 字符，未超过 240,000 原文输入上限。

此前模型输出校验只验证字段、引文和补读证据。完整报告包的容量在应用保存阶段才检查，超限因此错过模型已有的一次修正机会。减小片段能降低概率，但不能保证多标准合计引文一定放得下。

## 修复

新任务采用调度版本 17，在每步请求中明确实际报告来源 ID 和原有 90,000 字符预算。模型选择片段后，使用与调度器相同的引文渲染规则、原始来源位置、重复引文定位和 JSON 包装计算真实长度；超限进入已有的一次修正流程。

修正要求保留全部检查、实质问题、判定及必要来源，只能重新选择精确支持结论的引文并精炼表达。不能自动截断材料、减少必引来源、删掉检查、把不足或返修改成通过，也不无限重试。两次原答均保留；第二次仍超限则失败并保存诊断。调度器保存时的容量检查仍保留。

版本 1—16 的调度、请求字段、材料分块和历史报告不变。正在运行的正式复评及恢复仍使用冻结版本 15，未热换运行时。新机制不把旧失败报告追认为通过。
