# 设计64四领域最终核验工具准备

新增 `scripts/audit-design64-final.mjs`，用于正式队列及失败恢复全部结束后的统一核验。当前只有预检与运行中拒绝执行的检查完成；尚未生成四领域最终审计文件，不构成设计通过证据。

工具要求调用者明确指定最终检查点，核实最终工作进程和恢复等待器都已退出、四领域任务及报告完整，再按精确文件哈希反向核对从原队列到最终恢复的全链。原队列已出现失败，因此原队列自身不能冒充最终结果。

满足终态前置后，它读取一次一致的数据库快照，检查设计、正文、候选、事件、书稿及旧评审保持完整；当前任务和报告必须逐项匹配检查点，且不存在有效评审租约。随后使用冻结运行时重建四领域报告，并逐步离线重放全部已接受步骤的原始模型响应，包括格式修正回答。重放不接入模型服务。

最终结果还必须保留先前已独立核验的步骤、每条原始返修、完整人工争议清单，以及 v8 至 v11 草案的文件哈希。当前41条阻塞须原样保留。生成的文件仍标记为待人工争议核对，不能自动关闭问题、批准计划或启动正文。

最终结果还逐条保留历史材料不足：普通不足及未解决补读等待独立列出，不能被同标准下更严重的返修遮住；已明确补读解决的等待保留其解决步骤作为历史。该清单在原运行时重建和响应回放之后生成，不代替这些完整性验证。

在本轮仍运行的正式任务上，预检正确返回 `ready:false`，确认工作进程和恢复等待器都存活；直接执行也在数据库访问前被拒绝，没有生成最终文件，没有模型调用或生产写入。此检查只验证尚未就绪时的边界；完整重建和离线重放必须等四领域结束后实际执行，不能用预检替代。

预检命令：

```sh
node scripts/audit-design64-final.mjs data/audit-runtimes/design64-control/result.json --preflight
```

正式核验时指定实际最后一份恢复检查点，设置既有生产数据库连接，并使用 `node --experimental-strip-types` 运行。工具独占创建 `docs/audits/2026-10-16-design64-four-areas-audit.json`，拒绝覆盖已存在结果。
