# 在批次详情中核对实际原文范围

Design 64 的一次局部综合仅包含2/23个原文核查步骤，却把未直接附带的北航里程碑说成未设计。原始请求已保存来源目录、原文分片位置与综合子树范围，但界面没有展示这些范围信息。作者需要逐个打开材料才能发现建议依赖了未读来源。

本次在“原文与结果”的批次弹层新增“核对本步原文范围与完整来源目录”：

- 显示局部或全部报告汇总及所涵盖步骤数量；全部报告汇总仍不等于本步直接提供全部原文。
- 按保存的来源名称、里程碑标题、章节号或来源ID搜索，可筛选完整附带、部分附带、本步未直接附带和范围信息无法核实。
- 仅以实际材料及分片位置判断直接覆盖。报告中提及来源、引用局部原文或声明通过，都不计为直接完整提供。
- 分片须存在且长度匹配、无重叠、无缺口并覆盖声明总长度才标为完整。缺片、重复、截断或范围异常显示无法核实；旧接口缺目录时明确说明未知。
- 每个实际片段可打开核对原文；未附带的来源不提供伪造原文入口。来源目录不证明设计正确，也不会改变正式判定或解决问题。

验证：隔离目录内全部512项测试通过，前端类型检查及构建通过。4项新测试覆盖报告转述与原文区分、Unicode位置、缺口/截断/重叠/重复、旧数据未知以及导航名称不等于阅读证据。

浏览器核验使用冻结 `synthesis-1` 请求的只读副本，在独立5181端口预览实际组件：417个原始来源中仅1项完整附带；搜索 `ms_v2_voyage` 与其标题“有限航款与五日北行”均显示本步未直接附带；`plan/overview`的两个实际片段可打开，第二片段显示冻结请求中的依赖原文。截图保存于 `data/audit-previews/design64-source-coverage.png`。预览不访问生产写入接口。

本次不修改API、评审调度、模型提示或生产数据。8787/5180仍使用冻结运行时，5173未操作。生产正式评审持续运行；本次工程测试不代表设计质量通过。
