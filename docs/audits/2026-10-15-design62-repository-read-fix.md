# 大型作品聚合的并发读取修复

设计 62 的作品把设计历史、评审报告和可恢复任务以 JSON 形式保存。并发调用 Prisma `findUnique` 时，驱动会把多个完整聚合合并成一个 Rust/NAPI 字符串，曾出现 `Failed to convert rust String into napi string`，导致恢复入口在发出模型请求前停止。

仓储 `get` 改用单行 `findFirst`，保留按唯一作品 ID 查询的语义，避免并发请求被驱动批处理；书架 `list` 使用显式摘要字段，只读取 ID、标题、版本号和约定，不把不断增长的世界包、圣经、历史、评审和任务 JSON 传给列表调用。

回归测试覆盖两份作品的并发详情读取、缺失作品、书架摘要查询，并确认查询没有选取完整历史字段。生产数据库只读验证同时读取同一作品两次，53 个旧任务、59 份旧报告、设计与正文保护哈希、设计历史均逐项一致；书架读取成功，模型调用和数据库写入均为零。

隔离工作区完整 `node scripts/test-all.mjs` 通过。当前正在运行的正式评审仍绑定冻结仓储快照；本修复会用于下一次明确绑定的恢复，避免中途改变评审输入或租约状态。
