# 新最终稿须重新检查当前设计评审

发现最终稿入口仅检查世界／故事锁定、章节齐全和收束事件。章节曾经采纳后，即使新的设计评审缺失、要求返修或尚在执行，仍可创建新的 `final` 书稿并替代旧最终稿状态。原有生成与采纳入口的内容门槛不能阻止这条路径。

在隔离副本中，先用显式测试计划及四项测试评审完成百章书稿，再清空评审，断言最终稿应被拒绝。旧代码以 `Missing expected exception` 失败，确证入口绕过；没有对生产书稿执行该操作。

修复放在核心最终稿方法、任何设计快照和书稿状态写入之前：

- 必须存在批准计划，且绑定当前世界和故事圣经版本。
- 计划的卷数、章数与各卷范围必须匹配当前故事圣经，设计阻塞问题不能绕过。
- 与生成、采纳一致，达到长篇阈值时，当前批准计划绑定的世界、力量、人物、故事四项内容评审必须通过；缺失、过期、负面或未完成的新评审均拒绝生成新最终稿。

旧书稿继续按自身冻结的版本导出；本次不追改旧书稿，也不将局部设计评审解释为正文验收。已批准的计划与有效内容评审仅是最终稿的必要条件，已有锁定、完整章节和收束证据检查仍保留。

隔离验证：

- 核心测试覆盖无批准计划、未批准状态、旧世界绑定、错卷范围、缺失评审、新负面复评、未完成复评、改变书名导致旧报告过期。每次拒绝后原书稿集合逐字一致，旧最终稿仍为 `final`。
- 恢复有效评审后可以创建新修订，旧最终稿才变成 `superseded`。
- 真实 API 路由测试先冻结百章测试书稿，随后记录返修报告，最终稿请求返回 409；旧稿完整导出对象保持相等，书稿数量仍为 1。复评重新通过后可创建新稿。
