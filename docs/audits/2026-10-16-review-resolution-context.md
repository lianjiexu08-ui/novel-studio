# 补读处理记录成为可引用材料（schedule29）

原正式故事评审的综合22将第43→44章的等待重新判为材料不足，尽管该请求已经携带全部23项有效解决记录。它引用了子报告中的历史等待文字，却没有正确使用结构化处理记录。原始响应、正式报告及原设计均保留。

schedule29 将有效补读处理整理成独立来源 `review-resolutions/<sha256>`，加入每个综合请求的实际材料。记录包括原问题、所需来源、解决步骤、解决说明及证据数量和哈希；发布前按实际请求验证原问题和解决步骤的响应。它证明的是等待已有有效处理，不证明小说事实、全文通过或其他问题消失。该来源可直接引用，并随最终报告保留以支持重新载入后重构。

来源参与既有240,000字符容量检查，超限仍报错。版本1—28保持旧请求与渲染；新版本同时继承27的负面结论保留和28的补读规则上下文。没有自动将普通不足转为通过，没有部署到正在展示旧报告的冻结服务。

验证结果：

- 全量测试已通过；最终核心类型检查通过，设计评审回归45项通过。回归覆盖跨综合分支、直接引用、报告预算、JSON恢复、独立返修保留，以及伪造原问题或解决证据被拒绝。
- 对272份旧版本请求逐一比较，均与冻结实现一致。向134份旧综合请求追加新处理来源，最大材料157,829字符。此为单项材料增量验证，不是完整重新生成的29版评审。
- 对原故事综合22进行一次隔离真实模型复测，仅追加该来源，使用当前连接的 `gpt-5.6-luna`。一次调用完成，无修复调用；时间项直接引用第43章对应处理记录，并明确承认等待已经解决。七项局部结论均为通过。
- 保存响应离线重放结果一致；输入哈希、运行源码哈希及原正式检查点均核对通过。生产写入为零。

一次复测只能说明该材料改动对这个案例有效，不能保证所有语义判断正确，也不替代完整正式复评。人物身份、场景归属等既有报告错误仍需依据原文纠核。未批准计划，未生成正文。
