# 将已采纳事实完整传递给逐章写作模型

检查实际请求构建路径时发现两个断点：`contextManifestFor` 只强制保留人物状态和认知事件，较早的资源、法宝、关系及伏笔兑现会被最近事件窗口挤掉；网络写作器又只把选中事件中的 `knowledge_belief` 内容传给模型，其他事件只剩清单编号。最近八章之外的事实即使被选中，也无法由这些编号还原。此外，最新状态选择依赖 Map／数据库返回顺序，乱序读取可能把旧状态当成最新值。

修复后，按章节与稳定 ID 排序，再为每类事件、对象和字段保留最新有效记录，包含资源、物品、关系、人物弧光、秘密、承诺、开放线、分卷及情节落实。最近事件数量只是可选历史窗口的目标；必需记录超过该数量仍保留，材料预算不足时返回 `needs_split`，不靠删除必需事实获得可写状态。

网络写作器现在传递 `adoptedFacts` 原始事件及章节、版本、时间、证据，认知仍单列为 `adoptedKnowledge`。提示明确区分实际事实、未来设计、余额和增减，不能用有限事件摘录冒充完整累计账或凭空恢复资源。最近正文与事件均按本作品、本章之前、仍有效的条件过滤；不会因清单混入额外 ID 而发送未来稿、失效稿或其他作品内容。

验证：

- 先用旧代码运行 5 项新测试，全部失败，分别复现历史资源等事实遗漏、乱序误选旧状态、作品边界缺失、写作请求未携带事实内容，以及早章替换时额外清单带入不应读取的正文。
- 修复后 5 项通过；完整隔离测试 **314 项通过、0 失败**。前端类型检查及构建通过，仍有既有的大分包体积提示。
- 只读载入实际作品，用本地请求捕获替身检查第 1、50、101 章的请求构造；无真实模型调用、候选稿保存或正文采用。第 1 章没有历史事实；第 50 章选中并实际传递 186 条事件，157 条在最近八章之外；百章后的读取选中并传递 261 条最新事实，228 条在最近八章之外。所有事件均早于目标章，清单与实际载荷逐项相等。
- 保护哈希确认世界 29、圣经 59、全部计划、既有章节版本／事件／书稿／候选未改变。实际旧稿仍来自批准计划 10；上述读取不证明它符合设计 59，更不表示允许写第 101 章。

本次只修复事实选择与发送链路；没有声称模型必然理解每条事实，也没有把事件摘录当作完整资源守恒验收。后续仍需独立审查逐章正文和变化证据。运行中的评审及 API 没有重启，本代码在安全更新服务后生效。
