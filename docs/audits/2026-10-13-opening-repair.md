本轮修订第 1–12 章的创作计划，保存为世界 v16、故事圣经 v20、计划 v19（`plan_1d4b38201b024a4483917378cdbb08ee`）。全部仍待审核，批准计划仍为 v10。原正文没有替换，不能把新计划当作已经发生的故事事件。

## 生成链路修复

查明分组章纲模型此前没有收到 `worldPack`，只收到全书骨架、故事圣经、前后章纲和已采纳事实。即使骨架生成时看过规则，细化模型也无法准确核对所有功法、法宝和资源成本。本轮补入完整世界包，并要求余额不足时改变行动，不能靠残篇特例绕过门槛。

同时，故事圣经的旧逐章计划只传当前批次范围，前后衔接使用当前计划的邻近章纲。人物、关系、认知、弧光、分卷等其他材料保留；这不是截断内容评审材料。回归测试验证完整世界规则传入、只选择相应旧章纲、原圣经不被修改。

首次通过 API 分组生成时，GPT 通道断开，自动回退的 Gemini 通道返回模型不存在，计划没有部分保存。随后使用已配置的 `gpt-5.6-luna`，分两批各六章生成，并在本地保存每批完成结果。此临时检查点用于本次修复，不代表产品已经实现所有规划任务的自动断点续跑。后续根据实际返回结果作编辑修正，再通过正常 API 保存为提案。

## 编辑校正与同步

- “同级试剑”改为苏收敛真元、控制力度检查基础招式，避免混同双方境界。
- 过期三日查案许可不延长；旧试剑牌只能证明身份，不能继续授权调档。
- 气息追踪改为观察有粉尘的脚印，伤口也不能直接证明凶手人数。
- 救人紧接第 10 章同夜发生，取消“抽取即将完成却拖到隔日”的时间漏洞。
- 使团选择暂缓刑讯有自己的动机：编号已进入其留存文书，强行抹账会影响交割信用；它主张封存复核并控制证人，与戒律堂掩盖监管失察的利益不同。
- 开篇调整为第 1–18 日，给伤势与调查留出时间。第 13 章后的旧日期必须重排，不能悄悄继承旧时间线。
- 同步十二条圣经章纲、六个早期人物节点、三组关系的相关阶段、九鼎秘密的早期认知、主角目标和首个转折。苏在第 8–12 章只怀疑当地利益关联，第 13 章后的旧认知另列待修，避免直接跨到确定全案。

完整模型章纲、编辑改动、同步差异和失败记录见 [提案快照](2026-10-13-opening-repair-proposal.json)。新增阻塞问题明确：第 13–32 章仍含旧凝元／神海、争泉燃寿和过快晋阶，尚不能接上新开篇；必须继续重做古境准备、三年晋阶成本、灵泉用途、反派反制和南渡条件。
