# 分项评审进度刷新与历史证据传输

## 问题与修复

实际页面停留时，人物任务仍显示 5/19、故事任务仍显示 5/29；后台人物任务已完成 21/21，最终结论为材料不足，故事任务继续推进。手动刷新能读到正确结果，原因是卡片仅在挂载、版本变化或本页主动执行步骤后读取记录，没有观察其他执行端的进展。

- 可见页面定期读取进度，重新聚焦或切回页面时立即检查；隐藏页面不定时读取。
- 同一轮后台读取未结束时不叠加请求；切换作品、计划或卸载后，迟到响应不能覆盖新范围。
- 普通刷新保留已展开的证据。读取失败显示错误及“上次成功读取”的提示，不删除已有记录；切换范围才清空旧数据。
- 自动刷新只调用 GET，不启动、继续、批准评审或修改设计。

实测当前完整评审接口返回 **66,603,350 字节**。因此接口增加基于作品、所选计划、设计哈希、全部任务进度和不可变报告 ID 的 `revisionToken`。携带相同 `since` 时只返回未变化标记；发生新批次、失败、报告或计划范围变化时返回完整记录。历史原文、失败记录和负面结论保留，不截断材料。

新服务下每 15 秒检查一次。兼容尚未升级的服务：没有令牌时降低为约 60 秒检查，手动刷新及切回页面仍可立即读取。现有正式复评使用冻结运行时，故 API 服务升级继续等待所有复评写入者结束，不在此修复中重启服务或迁移数据库。

## 验证

- 浏览器实际观察：故事从 31/37 自动更新到 33/37，人物面板保持展开、仍显示材料不足；局部诊断通过没有覆盖正式结论。
- 29 项 API 测试通过。使用实际浏览器 API 模块接入 Fastify，验证未变化响应小于 150 字节、每个新批次及最终报告使令牌失效、切换计划不会误用原令牌、轮询不调用模型且不批准提案。
- Web TypeScript 与生产构建通过，仅有原有的大包体积提示。
- 测试使用隔离目录的 Prisma 客户端，生产客户端、数据库结构和服务进程未替换。
