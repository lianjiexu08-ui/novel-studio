# Design77：保留原判定的正式复核

本次修复的是评审机制：原始 `revise` 只能一直阻塞，即使后续已读到当时遗漏的规则，也没有正式处理路径。独立核对记录继续保留为意见，不会直接覆盖判定。

新增同任务定向复核。只允许当前版本、已停止且无执行权、连续已完成原文批次之后、任何汇总尚未尝试之前加入。一个原判定只接受一次正式复核，必须先完成已排入的复核；不支持对复核结果无限递归挑战。已完成任务或已运行汇总不能重排。

复核携带原批触及的**全部完整来源**、核对记录所引来源、显式补充来源及完整原判定。容量不够即拒绝，不截断来源。独立核对意见是待检验的质疑，不是设计证据。模型必须重新评审该标准的整项返修；通过必须显式声明解决对应问题，并引用原问题、每个原始依据、每个补充来源。仍有矛盾或不足时原返修继续阻塞；其他判定不被连带解除。

插入边界、核对记录快照和补充来源保存在任务中，复用已有执行权、失败保存和重试流程。最终完成必须重新构造原调度和插入顺序、验证每一步，再生成独立 `resolvedReconsiderations` 处理清单。原回答、原引文、原返修和旧失败不删除。

界面在独立核对记录中提供“提交正式复核”，显示待审、未解决或已解决，并可打开复核材料与结果。提交只排入下一步，不自动启动正文。

验证见相邻 `*-tests.json` 与 `*-preflight.json`。真实 Plan77 的 16 个已完成步骤、21 次调用已使用新代码逐条重放；原请求和结果保持一致。试剑争议的正式复核已预检：原输入不变，共 97 个完整来源、136055 字符，包含 `art_03`、`tech_04`、境界、相关公理和第18/20/21章。

此预检没有调用模型、没有生产写入，也不表示全书通过。世界41、圣经73、拟议计划77和已批准计划10继续保持原状态。真实调用、私库重放、生产应用与界面验证分别保存，不能用准备结果代替完成结果。

## 后续续跑边界

旧 `design77-notes-continuation/result.json` 停在 segment2，仍是21次调用、16步的不可变历史。**不能直接继续旧运行器**，因为它绑定旧运行时、39条核对记录和原调度。当前真实数据库有41条核对记录，力量任务另有一次显式复核、原文步骤之后重建的未开始汇总。续跑必须绑定新冻结运行时 `design77-formal-runtime`、本次 `apply-live-run.json` 和生产读回校验；前21次调用在旧日志，第22次为本目录 `001.started.json` / `001.response.json`。

正式复核仅解决指定原返修；其他不足、新冲突以及最终内容质量仍须逐步核验，不能据此扩展章纲、批准计划或批量生成正文。
