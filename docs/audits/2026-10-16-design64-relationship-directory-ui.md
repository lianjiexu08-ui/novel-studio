# 在评审来源目录显示关系双方

承接调度版本26的 `sourceRelationships`，评审批次的来源目录现在显示“林辰（char_01） → 苏凌霜（char_02）”这类原档双方标签。现有搜索同时检索该标签与来源ID，因此可按姓名、人物ID或关系ID定位。箭头保留原档方向，同名人物仍显示各自ID；没有明确姓名时只显示ID，旧批次没有这份目录时不补猜人物对。

目录仍按实际附带原文计算完整、部分、未附带或无法核实状态。关系标签不会生成原文片段或把未读材料变成已读，页面明确说明它只供定位，信任、合作及生效时点须打开原文核对。

在既有隔离工作区执行来源范围的5项针对性测试，全部通过；执行 `VITE_API_URL=/api npm run build -w novel-studio-web`，类型检查和生产构建通过，仅保留已有大包体积提示。日志为 `/tmp/novel64-relationship-directory-build.log`。新增用例核对同名不同ID、方向、缺失姓名、旧目录兼容，以及标签不能改变原文覆盖状态。

本次未部署，线上冻结版本25不追溯添加新目录；没有生产写入、模型调用或设计批准。界面在未来读取版本26保存的批次时才显示对应双方信息。本次为代码、测试和构建验证，未声称当前正式界面已具有新目录。
